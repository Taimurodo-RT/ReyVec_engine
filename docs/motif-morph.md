# Перетекание: что движок принимает от Motif

Договор между ReyVec и редактором Motif о перетекающих фигурах (морфинг). Движок главнее: Motif выстраивает свой инструмент перетекания под этот договор. Устройство движка описано в `docs/decisions/0009-vector-layer.md`, раздел «Перетекание».

Статус на 2026-11-01:
- части 1–3 работают (этап 3.3б);
- автоматическое сопоставление по длине контура запланировано;
- подсказки художника (часть 4) пока только договор, в движке их ещё нет.

## 1. Что такое перетекающая фигура

Одна залитая фигура с несколькими **ключевыми контурами** (не меньше двух). Это ровно то, что в Motif уже есть как `morph star heart` у фигуры и `forms "…" "…"` у `path`.

- **Контур:** обычный путь из прямых, квадратичных и кубических кривых Безье (как SVG `d`).
  - В контуре может быть несколько кусков (дырки, отдельные части).
  - Незамкнутые куски движок замыкает прямой.
- **Число кусков и точек у ключевых контуров может отличаться.** Подгонять их в Motif не нужно: движок сам приводит контуры к одному устройству.
  - Недостающий кусок вырастает из точки. Так из круга получается кольцо.
- **Заливка:** правило NonZero или EvenOdd и закраска. Они общие для всех ключевых контуров фигуры.
- **Закраска:** цвет или градиент (с этапа 3.4а). Градиент как в SVG: линейный (`start`, `end`) или радиальный (`center`, `radius`, необязательный `focus`), точки цвета (доля 0..1 и цвет sRGB с прозрачностью), за краями `pad`/`reflect`/`repeat`, необязательное преобразование (как `gradientTransform`). Координаты градиента в координатах фигуры: при перетекании он стоит на месте, форма перетекает под ним.
- **Только заливки.** Обводка у перетекающей фигуры не поддерживается: её пришлось бы заново резать каждый кадр. Если обводка нужна, рисуйте её отдельной заливкой-контуром (кольцом) с теми же ключевыми контурами.

## 2. Значение перетекания

Каждый кадр у экземпляра фигуры есть одно число `morph`:

| `morph` | Форма |
| --- | --- |
| 0 | первый ключевой контур |
| 1 | второй |
| 1.5 | ровно посередине между вторым и третьим |
| меньше 0 или больше последнего | обрезается до первого или последнего |

- **Между соседними ключевыми контурами движок смешивает точки по прямой** (линейно). Плавность, пружины и паузы задаёт Motif кривой анимации самого числа `morph`: дорожка `blob.morph 0: 0 ease-in-out | 1: 1` даёт плавный ход, `hold` даёт скачок.
- **Перетекание идёт только к соседнему контуру.** Чтобы фигура перешла из первого в третий, минуя второй, ключевые контуры нужно расставить в другом порядке или сделать отдельную фигуру.
- Цвет и прозрачность при перетекании не смешиваются сами. Если нужно, их анимирует оттенок экземпляра (`tint`) отдельной дорожкой.

## 3. Что движок делает сам, один раз при загрузке

- Сводит контуры друг к другу: число кусков, число кривых, направление обхода, начало каждого куска. Сейчас сопоставление простое: кривые делятся по длине, начало сдвигается к ближайшей точке. Запланировано равномерное сопоставление по длине контура, чтобы промежуточные формы меньше искажались (`docs/vector-bottlenecks.md`, пункт 20).
- Готовит треугольники для видеокарты.

Каждый кадр процессор только записывает число `morph`, формы смешивает видеокарта. Поэтому ключевые контуры задаются при загрузке сцены, а не меняются каждый кадр.

## 4. Подсказки художника (будущий инструмент Motif)

Иногда автоматика не угадает замысел: например, рот должен открываться от уголков, а не от середины. Для этого художник ставит **метки соответствия** между двумя соседними ключевыми контурами. Метки необязательны: без них работает автоматика, с ними движок подгоняет сопоставление так, чтобы метки совпали, а остальное распределяет равномерно между ними.

Что движок будет принимать:

- **Пара кусков:** «кусок `i` контура `k` становится куском `j` контура `k+1`». Это нужно, когда в контурах несколько частей и автоматика путает, какая во что превращается. Без пары куски сопоставляются по порядку.
- **Точка роста:** для куска, которого нет в соседнем контуре, место, из которого он вырастает или в которое исчезает. Без неё это середина куска.
- **Пара точек:** «место `a` на куске `i` контура `k` становится местом `b` на куске `j` контура `k+1`».
  - Место задаётся долей длины куска от его начала, от 0 до 1. Доля, а не номер узла: так метка переживает правку контура, добавление узлов и разбиение кривых.
  - Motif при сохранении может пересчитать «вот этот узел» в долю длины сам.
  - На одну пару кусков допускается несколько меток. Они должны идти в одном порядке по кругу на обоих кусках (кусок замкнут, поэтому после доли 1 снова идёт 0: метки 0 → 0.534 и 0.5 → 0 идут в одном порядке), иначе перетекание перекрутится; такие метки движок отклонит с понятной ошибкой.

Пример, как это могло бы выглядеть в `.msc`. Синтаксис окончательно выбирает Motif, здесь только смысл:

```
path mouth d "…закрытый рот…" forms "…открытый рот…"
morph-pin mouth 0 -> 1 piece 0 at 0.00 -> 0.00   // левый уголок остаётся левым уголком
morph-pin mouth 0 -> 1 piece 0 at 0.50 -> 0.50   // правый уголок остаётся правым
```

## 5. Что Motif передаёт движку, итог

| Данные | Когда | Обязательно |
| --- | --- | --- |
| Ключевые контуры по порядку (пути Безье) | при загрузке | да, не меньше двух |
| Правило заливки и закраска (цвет или градиент) | при загрузке | да |
| Пары кусков, точки роста, пары точек | при загрузке | нет |
| Число `morph` у экземпляра | каждый кадр (из анимации) | да |

## 6. Файл от Motif (`*.reyvec.json`, версия 1)

Motif пишет его командой `motif morph сцена.msc -o сцена.reyvec.json` или кнопкой «Перетекающие фигуры в JSON…» в «Экспорте». Движок не подключает код Motif и читает только этот файл (решение Романа, 2026-11-01). Чтение файла движком появится вместе с импортом SVG (3.5). Первый пример от Motif проверен: все контуры разбираются, перетекание строится.

```jsonc
{
  "format": "reyvec-morph",   // всегда первым
  "version": 1,               // растёт при несовместимых изменениях
  "y": "up",                  // y вверх, как в движке
  "units": "px",              // координаты в пикселях Motif; движок делит на 100 (100 пикселей = 1 единица сцены)
  "fps": 60.0,                // частота записанных значений morph
  "shapes": [{
    "board": "Морфинг", "id": "mouth",
    "fill_rule": "nonzero",                 // или "evenodd"
    "color": "#9d3b5a", "alpha": 1.0,       // sRGB; или "gradient" (см. ниже)
    "contours": ["M -40 0 C …", "M 30 10 C …"],  // ключевые контуры, SVG d, в координатах фигуры
    "morph": 0.0,                           // значение без анимации
    "marks": [{ "step": 0, "from": { "piece": 0, "at": 0.0 }, "to": { "piece": 0, "at": 0.534 } }],
    "animations": [{ "id": "…", "animation": "Flow", "duration": 4.0, "loop": true,
                     "morph": [0.0, 0.0001, …] }]
  }]
}
```

- **`marks`:** `step` k — метка между контурами k и k+1; `piece` — номер куска; `at` — доля длины куска. Пары кусков и точки роста (часть 4) пока не пишутся: добавятся как `"pieces": [{ "step", "from", "to" }]` и `"grow": [{ "step", "piece", "at": [x, y] }]`, когда Motif их сделает.
- **`animations[].morph`:** значение на каждый кадр с уже применёнными кривыми хода. Значение i относится ко времени i / fps, оба конца включены: 4 с при 60 кадрах дают 241 значение, последнее на 4,0 с. Между записанными значениями движок смешивает по прямой.
- **Градиент** (когда Motif начнёт его писать) вместо `color` и `alpha`: `"gradient": { "kind": "linear", "start": [x, y], "end": [x, y] }` или `{ "kind": "radial", "center": [x, y], "radius": r, "focus": [x, y] }`, плюс `"stops": [{ "at": 0.0, "color": "#rrggbb", "alpha": 1.0 }, …]`, `"spread": "pad" | "reflect" | "repeat"` и необязательный `"transform": [a, b, c, d, e, f]`. Координаты как у контуров.
- **Положение фигуры на холсте Motif** (`at`, поворот, масштаб) не обязательно: где стоит фигура, решает игра. Если Motif запишет его как `"transform": [a, b, c, d, e, f]` у фигуры, движок сможет показать сцену так же, как предпросмотр Motif.
- Чего движок не показывает (обводку у перетекающей фигуры, смену цвета между контурами), Motif в файл не пишет и предупреждает художника.
