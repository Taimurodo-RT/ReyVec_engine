# 0015. Управление: действия, привязки, поведение и схемы (6.12)

Дата: 2026-11-04. Статус: принято.

## Задача

Роман: управление должно быть таким же «компонентом», как остальное, потому что в разных
играх оно разное и влияет на разное; для меню и для игры нужны разные схемы; спорные выборы
(куда бить мышью, какой кнопкой двигать камеру) — не решать за игрока, а дать выбрать в
настройках; потом будет визуальный редактор управления, поэтому всё должно быть описано
данными. Проект схемы: [документ](https://claude.ai/artifact/P6yhZZdLnojAyR74pc8V1M).

## Решение

Четыре таблицы данных в `crates/reyvec-app/src/controls.rs`. Меню настроек строится по ним,
будущий редактор будет строиться по ним же; код, который знает про конкретную кнопку, есть
только в разборе событий окна.

### 1. Действия

`Action` (`reyvec-game`) — что умеет игра: влево, вправо, вверх, вниз, прыжок, рывок, удар.
Логика игры спрашивает только действия и никогда не видит клавиш. Каждое действие —
«кнопка» (нажато / отпущено). Позже добавятся «ось» (стик, колесо как величина) и «точка».
Точка уже есть одна: **прицел** — курсор мыши в координатах сцены, его каждый кадр получает
поток логики (`SceneLogic::set_aim`), а нажатие, пришедшее с мыши, запоминает, где был
курсор в этот момент (`press_aimed`, `InputFrame::aimed`).

### 2. Привязки

Источник (`Input`) → действие. Источник — клавиша (по месту на клавиатуре, не по букве, так
что раскладка не важна), кнопка мыши (левая, правая, средняя, «назад», «вперёд») или щелчок
колеса (вверх, вниз). У действия до `MAX_KEYS` = 4 привязок; один источник принадлежит одному
действию — назначение на другое снимает его с прежнего. Служебные клавиши (Esc, `~`) не
назначаются.

Привязки по умолчанию: стрелки, пробел — прыжок, Shift / X / **правая кнопка мыши** — рывок,
Ctrl / A / **левая кнопка мыши** — удар.

### 3. Поведение

`OPTIONS` — список выборов. У каждого: имя в файле, подпись в меню, подсказка (что он
делает), варианты (имя в файле + подпись) и вариант по умолчанию. Сейчас два:

| В файле | Варианты | По умолчанию |
|---|---|---|
| `удар мышью` | `к курсору` — герой разворачивается к курсору и бьёт; `по взгляду` — бьёт туда, куда смотрит | `к курсору` |
| `камера в игре` | `средняя`, `правая`, `левая`, `нет` — какой кнопкой мыши отодвигать камеру во время игры | `средняя` |

Удар клавишей всегда идёт по взгляду. Если кнопка камеры назначена ещё и действию, действие
главнее. Новый выбор = новая строка таблицы и одна проверка там, где он действует; меню
покажет его само.

### 4. Схемы

Схема — набор того, что значат нажатия в одном состоянии программы. Они лежат стопкой,
верхняя первая; нажатие уходит первой схеме, для которой оно что-то значит
(`Controls::route`):

| Схема | Когда в стопке | Что забирает |
|---|---|---|
| Консоль | открыта консоль | `~` и Esc закрывают; всё остальное — набор текста |
| Меню | открыто меню паузы | `MENU_KEYS`: ↑/W, ↓/S — выбор строки, Enter/пробел — нажать, Esc — назад; остальное — щелчки мышью по меню |
| Игра | сцена с героем | Esc — меню, `~` — консоль, привязки действий, кнопка камеры |
| Песочница | всегда, внизу | клавиши песочницы (сцены, MSAA, снимок F12…), колесо — приближение |

Так меню и консоль не пропускают нажатия в игру, а клавиши песочницы работают, пока их не
заняла игра. Позже у каждой игры будет своя схема «Игра» из её файла (`input.ron` рядом со
сценой), а компонент «Управляемый» на предмете скажет, кто получает действия.

### Файл

`settings/controls.ron` рядом с программой — то, что выбрал игрок, поверх умолчаний:

```text
(
    клавиши: {"прыжок": ["Space", "KeyW"], "удар": ["KeyA", "МышьЛевая"]},
    поведение: {"удар мышью": "к курсору", "камера в игре": "средняя"},
)
```

Имена мыши: `МышьЛевая`, `МышьПравая`, `МышьСредняя`, `МышьНазад`, `МышьВперёд`, колесо —
`КолесоВверх`, `КолесоВниз`. Неизвестные имена и выборы пропускаются с предупреждением,
недостающие берутся по умолчанию; старый файл из 6.10б (без `поведение`) читается как есть.
